生成商品信息运营规范 HTML 时,遵循"脚本抽料 → 模型读 PDF 重建结构 → 对照 PDF 逐屏审查"三段式,不得把 batch_generate.py 的机械草稿直接当成品交付。

**Why:** 源 Word 文档是从 PDF 导出的,导出过程破坏了层级(无 heading 样式,模块标题和正文都用 `1、2、` 编号,合并单元格丢失)。纯 Python 启发式无法区分"模块标题 `1、主图规范`"和"正文编号 `1、视频画面需清晰`",也无法理解 t2 那种 10×4 rowspan 合并对比矩阵、t8 灰底/红底交替表头等语义。上一轮偷懒跳过模型重建、直接交草稿,被用户挑出 10 处结构错误。用户明确指出"PDF 才是最原始、最正确的结构"。

**How to apply:** 每次任务都要求用户提供对应 PDF(用户已确认每次都能提供)。脚本只负责确定性脏活(解压 docx、抽文本、导图片、导表格单元格数据 → manifest.json);层级判定和表格语义由模型看 PDF 决定;HTML 生成后再对照 PDF 逐屏比对修正。8 个一级模块固定为:主图规范/主图视频/长标题/短标题/通用卖点/主推标签/品质标签/属性,标题去掉 `N、` 前缀(外层已有 01-08 序号)。
